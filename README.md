# mecraft

Веб-страница с содержимым ME-сети из GTNH: предметы с иконками, жидкости,
процессоры крафта, заказы крафта из браузера и поддержание уровня запасов.

Компьютер OpenComputers в игре держит TCP-соединение с сервером на Go и
шлёт ему состояние сети; сервер показывает его на странице (htmx) и
передаёт заказы обратно в игру. Шаблоны, стили, htmx, иконки и Lua-скрипт
вшиты в бинарник.

```
OC (oc/mecraft.lua) ──TCP, Lua-таблицы по строкам──► mecraft (Go) ◄──HTTP── браузер
```

## Сервер

Нужны Go 1.24+ и [just](https://github.com/casey/just).

1. В игре выгрузи иконки: NEI → Options → Tools → Data Dumps →
   «Панель предметов», переключи формат на **PNG** и нажми «Выгрузить».
   Поиск NEI перед этим очисти, иначе выгрузится только найденное.
2. Скопируй иконки в репозиторий (в git они не попадают):
   ```
   just icons
   ```
   По умолчанию берётся дамп из инстанса Prism `GT_New_Horizons_2.9.0_Java_17-26`.
   Другой инстанс: переменная `GTNH_INSTANCE=<путь к .minecraft>` или
   `just icons "<путь к itempanel_icons>"`.
3. Собери и запусти:
   ```
   just run секрет
   ```
   `секрет` — пароль для OC; без него берётся `token` из `mecraft.json`.
   Страница: http://localhost:8080

Остальные команды: `just` (список), `just build`, `just build-linux`,
`just check`, `just clean`.

### Настройки: `mecraft.json`

Все настройки и уровни запасов лежат в одном файле `mecraft.json` в папке,
откуда запущен сервер (для `just run` — папка репозитория). Если файла нет,
сервер создаст его при запуске:

```json
{
  "http": ":8080",
  "oc": ":7777",
  "token": "",
  "maintainEvery": "5s",
  "rules": []
}
```

- `http` — адрес страницы;
- `oc` — порт, к которому подключается OC;
- `token` — пароль, который должен прислать OC; пустой — без проверки;
- `maintainEvery` — как часто проверять уровни запасов (`5s`, `1m`);
- `rules` — уровни запасов; их удобнее править на странице, сервер сам
  записывает их сюда.

Меняешь `http`, `oc`, `token` или `maintainEvery` — перезапусти сервер.

Флаги командной строки важнее файла, но в файл не записываются:
`-http`, `-oc`, `-token`, `-maintain-every`, например
`mecraft.exe -token секрет -http :9000`. Другой файл настроек:
`-config путь/к/файлу.json`.

Без шага 2 всё работает, только вместо иконок будут заглушки.

## Компьютер в игре

Нужно:
- **Internet Card**;
- **Adapter** вплотную к ME Controller или ME Interface;
- побольше памяти: полный список сети приходит одной таблицей.

Установка (в шелле OpenOS), нужен только один файл:

```
wget -f https://raw.githubusercontent.com/fess932/mecraft/main/oc/mecraft.lua /bin/mecraft.lua
```

Скрипт пользуется встроенной в OpenOS библиотекой `serialization`, больше
ничего ставить не надо. Если раньше ставил `/lib/json.lua`, его можно удалить.

Запуск:

```
mecraft <IP сервера> 7777 секрет
```

`7777` — порт из поля `oc`, `секрет` — значение `token` из `mecraft.json`
(если токен пустой, третий аргумент не нужен).

Остановка: Ctrl+C. При обрыве скрипт сам переподключается каждые 5 секунд.
Чтобы запускался при загрузке, добавь строку запуска в `/home/.shrc`.

### Если сервер на этом же компе или в локальной сети

OpenComputers по умолчанию запрещает подключения к `127.0.0.1` и локальным
адресам (`192.168.*`, `10.*`, `172.16–31.*`). В
`config/OpenComputers.cfg`, секция `internet`, добавь разрешение
**первой** строкой `filteringRules`, указав IP сервера:

```
filteringRules=[
  "allow ip:192.168.1.10",
  "deny ip:127.0.0.0/8",
  ...
]
```

Перезапусти игру.

## Поддержание уровня

Нажми на предмет или жидкость и заполни «Держать уровень»:
- **не меньше** — сколько штук (для жидкостей — литров) должно быть в сети;
- **заказывать по** — сколько заказывать за раз. Пусто — заказывается
  недостача до уровня.

Раз в 5 секунд сервер сравнивает запас с уровнем и, если не хватает,
заказывает крафт. Пока заказ считается или крафтится, второй не
отправляется. Как только заказ готов, а уровень ещё не набран, сразу
уходит следующий. Если заказ упал (например, не хватило ресурсов),
повтор через 5 с, потом 10 с, 20 с, 40 с и дальше раз в минуту; первый
успешный заказ сбрасывает задержку.

### Переработка ресурса

Второй режим в том же окне — «Перерабатывать ресурс»: крафтить предмет,
пока в сети больше порога выбранного ресурса. Например, открой натрий,
выбери в поиске гидроксид натрия, «Пока ресурса больше» 10 000,
«Заказывать по» 64 — партии натрия заказываются одна за другой, пока
гидроксида не останется 10 000. OC не видит входы шаблона, поэтому ресурс
выбирается руками; последняя партия может уйти немного ниже порога.
Поле «… не больше» ограничивает сам предмет: заказы идут, пока ресурса
больше порога и предмета меньше лимита; пусто или 0 — без лимита.
Задержки при ошибках те же. Такие правила тоже видны в фильтре «Уровни»,
полоска у них синяя, пока идёт переработка, и зелёная, когда ресурс
переработан до порога или предмет дошёл до лимита.

Фильтр «Уровни» на вкладках предметов и жидкостей оставляет только то, для
чего задан уровень, и складывается с остальными фильтрами; без «В наличии»
видно и то, чего сейчас нет в сети. Полоска сверху слота —
запас относительно уровня (жёлтая — не хватает, серая — уровень выключен),
состояние и причина последней ошибки — в подсказке и в окне предмета.
Правила хранятся в `mecraft.json` (поле
`rules`) и переживают перезапуск. Работает только пока запущены сервер и скрипт в
игре; для правил, которые должны работать всегда, есть ME Level Maintainer
из AE2 Fluid Crafting.

## Как это работает

- При подключении OC шлёт полный список предметов и жидкостей, дальше
  только изменения (события `network_item_changed` /
  `network_fluid_changed`) раз в полсекунды. Раз в 5 минут и по кнопке
  «Синхронизировать» список шлётся целиком заново, чтобы поправить
  пропущенные события.
- Процессоры и энергия ME обновляются раз в 5 секунд.
- Иконка ищется по названию предмета, как его видит игра (`label`), тем же
  правилом, по которому NEI называет файлы. Если в игре и при выгрузке
  иконок разный язык, иконки не найдутся: выгружай на том же языке.
- Предметы, у которых совпадают ID и подтип, различаются по названию: NBT
  в OC не передаётся.

## Протокол

Одно сообщение на строку: Lua-таблица в том виде, в каком её пишет и читает
`serialization` из OpenOS (`{type="craft",amount=64,...}`). В OC разбор идёт
встроенным `load`, на стороне Go — свой парсер (`luaval.go`), проверенный
тестами на настоящем `serialization.lua` (`testdata/`). Поле `type` — тип
сообщения.

OC → сервер: `hello {token}`, `items_begin`, `items {items}`, `items_end`,
`item_delta {items}` (size со знаком), `fluids {fluids}`,
`fluid_delta {fluids}`, `cpus {cpus}`, `power {stored,max,usage,injection}`,
`job {job,state,reason}`.

Сервер → OC: `craft {job,name,damage,label,amount}`, `resync`.
